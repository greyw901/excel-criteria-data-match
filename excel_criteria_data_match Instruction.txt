  Excel Criteria Data Match v1.2_20261113 — Instruction

----------------------------------------------------------------
  FOR USERS
----------------------------------------------------------------

WHAT IT DOES
Takes one or more amount columns from an Excel sheet (the DATA
source) and lines them up against the row layout of another
Excel sheet (the REFERENCE source), by matching the label text in
both (e.g. "TRADE DEBTORS", "TOTAL FIXED ASSETS"). It writes a new
Excel file that mirrors the reference sheet's exact row order and
spacing, with the matched amount(s) next to each label — so the
amount column(s) can be copied straight into the real workbook.

If the same label text repeats in a sheet (e.g. a section header
and a later total that happen to share the same wording), it
matches the 1st occurrence of that text to the 1st, the 2nd to
the 2nd, and so on top to bottom — not just the first match.

You can pull more than one DATA column in a single run (e.g.
ACTUAL + BUDGET + VARIANCE together) instead of re-running the
tool once per column.

GETTING STARTED
Put excel_criteria_data_match.exe (or excel_criteria_data_match.py)
in the same folder as the Excel files you want to match (.xlsx,
.xlsm or .xls only — other file types are ignored). Double-click
the .exe, or run the script with:

   python excel_criteria_data_match.py

(Use "python", not "py" — see TROUBLESHOOTING if that's unclear.)

The files can stay open in Excel — the tool only reads them — but
save them first: it reads what is on disk, not unsaved edits.

HOW THE SCREENS WORK
The window is cleared for every step. Each screen starts with the
tool's name in a ==== box, then what you have already chosen,
then the question, a ---- line, the keys you can press, and the
prompt where you type. Anything in [ ] is a key you press:

   [Enter]  continue (on the confirm screens only)
   [#]      pick from the list
   [0]      back ONE screen ("[0] Exit" on the first screen closes
            the window straight away)
   [00]     cancel and close, from the 3rd screen on; shows
            "Cancelled." and waits for [Enter] to close...

If what you typed is not accepted, the same screen comes back with
the reason just above the question, e.g.:

   Error: Invalid Input - range 'H:F' must be ascending (e.g. F:H, not H:F) - use a comma list for custom order

SELECTING THE REFERENCE SOURCE
The script lists every Excel file in the folder:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Select REFERENCE source:

      [1] "OAP PL 202606.xls"
      [2] "OAP(consolidated) New & Old CP_AAA_202606_Fomulated.xlsx"
      [3] "PL_OAP matched 2606.xlsx"

   --------------------------------------------------------
   [#] Select
   [0] Exit

   Reference:

Type the file number and press Enter. Next, pick the sheet and
the column that holds the reference labels, in the form
<sheet number>_<column letter>:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Reference : "OAP(consolidated) New & Old CP_AAA_202606_Fomulated.xlsx"

   Select REFERENCE sheet & col:

   e.g. 4_F

      [1] "FXCOLROWHIDES"
      [2] "CSV_Conv.def"
      ...
      [13] "PL_OAP"
      ...

   --------------------------------------------------------
   [#]_[Col] Select
   [0] Back

   Sheet & col:

Typing "13_F" means sheet 13 (PL_OAP), column F. [0] goes back to
the file list. Pressing Enter with nothing typed is not accepted
("Error: Invalid Input"), so a stray Enter never moves you on or
closes the tool.

You'll then see a confirmation screen:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Confirm REFERENCE source:

      File  : "OAP(consolidated) New & Old CP_AAA_202606_Fomulated.xlsx"
      Sheet : "PL_OAP"
      Col   : F

   --------------------------------------------------------
   [Enter] Continue
   [0] Back
   [00] Cancel & exit

   Ans:

SELECTING THE DATA SOURCE
Same idea: pick the file, then give the criteria column (the labels
to match on) PLUS one or more data columns (the amounts), in the
form <sheet number>_<criteria column>_<data column(s)>. [0] on the
DATA file list goes back to the REFERENCE confirmation, so nothing
already chosen is lost. The REFERENCE choice stays shown at the top:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Reference : "OAP(consolidated) New & Old CP_AAA_202606_Fomulated.xlsx"!PL_OAP, col F
   Data      : "OAP PL 202606.xls"

   Select DATA sheet & cols:

   e.g. 1_D_I        one data col
        1_D_F:H      range: F, G, H
        1_D_F,G,B    list: F, G, B

      [1] "P&L DETAILED"

   --------------------------------------------------------
   [#]_[Col]_[Col(s)] Select
   [0] Back
   [00] Cancel & exit

   Sheet & cols:

The data-column part accepts:
  - one letter          e.g. "I"       -> just column I
  - a range             e.g. "F:H"     -> F, G, H (ascending only;
                                          "H:F" is rejected — use a
                                          list instead for custom order)
  - a comma list        e.g. "F,G,B"   -> exactly F, then G, then B
  - a mix of both       e.g. "F:H,B"   -> F, G, H, then B

Output columns follow the order you typed, so a list lets you
deliberately reorder (e.g. put last year before this year). The
criteria column can't also appear as a data column, and repeating
the same column twice is rejected.

Typing "1_D_E:H" means sheet 1, criteria column D, data columns
E, F, G, H — confirmed as:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Reference : "OAP(consolidated) New & Old CP_AAA_202606_Fomulated.xlsx"!PL_OAP, col F

   Confirm DATA source:

      File         : "OAP PL 202606.xls"
      Sheet        : "P&L DETAILED"
      Criteria col : D
      Data cols    : E, F, G, H

   --------------------------------------------------------
   [Enter] Continue
   [0] Back
   [00] Cancel & exit

   Ans:

READING THE RESULTS
After both sources are confirmed, the script reads both sheets,
matches them, and writes the output. You'll see a run report:

   ========================================================
   Excel Criteria Matcher
   ========================================================

   Inputs: 2
      1. "<reference file>"
      2. "<data file>"

   Reference sheet & col : "<sheet>", <letter>
   Data sheet & cols     : "<sheet>", criteria <letter>, data <letters>

   Processing
   Reading reference ...
   Reference rows : <n>
   Reading data ...
   Data rows : <n>
   Matching ...
   Matched : <n>
   Unmatched reference : <n>   (sheet "Unmatched Reference")
   Data overflow : <n>   (sheet "Data Overflow")
   Writing output ...

   Outputs: 1
      1. "<output file name>"

   Elapsed: 0.3s

   --------------------------------------------------------
   [Enter] to close...

The "Unmatched reference" and "Data overflow" lines only appear
when there is something to report:

  - Unmatched reference — a label exists in the REFERENCE sheet
    but no matching text was found in the DATA sheet. Usually
    means the two sheets' wording doesn't line up exactly (a
    typo, a renamed line, a title line), or the reference row
    genuinely has no amount. Listed on the output file's
    "Unmatched Reference" sheet.

  - Data overflow — the DATA sheet has MORE occurrences of some
    label than the REFERENCE sheet has rows for. Those amounts
    have nowhere to go on the "Matched" sheet — they are listed
    on the output file's "Data Overflow" sheet instead, so nothing
    silently goes missing. Check these rows manually before
    relying on the output as complete.

OUTPUT FILES
The output workbook is named "<reference sheet> matched <YYMM>.xlsx"
when the data file's name contains a year+month (e.g. "202606"),
or "Match Result_<reference sheet>_<today's date>.xlsx" otherwise.
It has up to three sheets:

  - "Matched" — row 1 is a header ("Reference_<ref col letter>"
    in column A, then "Data_<letter>" for each selected data
    column). From row 2 down, column A is the reference label and
    the data columns hold the matched amount(s), at the SAME
    relative row position as the reference sheet shifted down by
    one (reference row 1 -> output row 2, and so on) — so when you
    copy the value columns into your real workbook, skip row 1 and
    the rows still line up.
  - "Unmatched Reference" — only present if any reference label
    found no match (Reference Cell | Reference Label | Source).
  - "Data Overflow" — only present if anything overflowed
    (Criteria Cell | Data Criteria | Data Col <letter> for each
    selected data column | Source).

If a file of that name already exists, "_1", "_2" etc. is
appended — nothing is overwritten.


----------------------------------------------------------------
  FOR DEVELOPER(S)
----------------------------------------------------------------

MATCHING LOGIC
Matching is purely by exact label text (leading/trailing
whitespace stripped) plus an occurrence counter: the Nth time a
given text appears top-to-bottom in the REFERENCE column is
matched to the Nth time that same text appears top-to-bottom in
the DATA criteria column. This is the only way implemented to
disambiguate a repeated label (e.g. a section header and a later
total sharing the same wording) — there is no fuzzy matching, no
case-insensitivity, and no attempt to match by row position
instead of text. See build_data_lookup() / build_output_rows().
Once a key matches, ALL of its selected data columns are pulled
as a tuple — a blank cell in one of those columns stays blank in
the output rather than being skipped, so column positions never
drift relative to the header.

Any DATA criteria-column occurrence that is never claimed by a
REFERENCE row (lookup key not in used_keys) is "overflow" — see
find_overflow(). Overflow and unmatched reference labels are data
exceptions, not script failures: each goes on its own sheet in the
output workbook (written only when non-empty), and the run report
shows only a count line pointing to that sheet. There is no error
log for them — the output file itself is the record.

SCREENS AND NAVIGATION
The six prompt screens (REFERENCE file, sheet & col, confirm; DATA
file, sheet & cols, confirm) run as a step machine in
select_sources(). Signals are exceptions:

  Exception      Raised when                       Caught in
  -------------  --------------------------------  ------------------
  GoBack         [0] on any screen but the first   select_sources()
                                                   -> one step back
  UserExit       [0] on the first screen           main() -> returns,
                                                   window closes
  UserCancelled  [00] from the 3rd screen on       main() -> Cancelled.
                                                   + [Enter] to close...

read_choice() handles the navigation keys for every screen: [00] is
matched on the whole input before any parsing, then [0]. Every
screen starts with open_screen(choices, error): clear ("cls"),
banner, the choices made so far, then the invalid-input notice.
A confirm screen's choices block leaves out the source being
confirmed — its details are the screen body. Invalid input sets
the notice and loops; for the sheet & col screens the notice
carries the specific reason (pattern, range, overlap, duplicate).

DATA COLUMN SELECTOR PARSING
The Data Col(s) token (range/list/mix) is expanded by
parse_data_columns() into an ordered list of column letters before
any reading happens — ranges must be ascending (column_index_from_
string(start) <= end), otherwise it raises ValueError with a
message telling the user to use a comma list instead. Duplicate
columns and a criteria/data-column overlap are both rejected in
prompt_select_sheet_cols_data() before the source is accepted.

ROW RANGE
The REFERENCE sheet's usable row range is 1..last row with a
non-empty value in the criteria column; the DATA sheet's is
1..last row with a non-empty value in the criteria column OR any
selected data column. This avoids dumping hundreds of blank
trailing rows some workbooks report via max_row/nrows (openpyxl in
particular can report a much larger max_row than the sheet's real
content).

FILE READING
.xls files are read with xlrd (the legacy format); .xlsx/.xlsm
with openpyxl, data_only=True so formula results are read, not
formula text. Both are read in full (not streaming) since these
workbooks are at most ~1000 rows — not worth the added complexity
of a streaming reader.

OUTPUT FORMATTING
The output is a new workbook, so openpyxl writes it from scratch.
Header rows are bold and centred. Column widths are measured from
the content (numbers by their formatted 1,234.56 length) plus a
fixed margin (WIDTH_MARGIN); text columns are capped at
MAX_TEXT_WIDTH. The amount columns on a sheet share one width so
they read aligned.

DEPENDENCIES
openpyxl, xlrd (pywin32 is NOT required by this script).

VERSIONING
v{major}.{minor}_{YYYYMMDD}. Update VERSION in the script,
version_info.txt and this file together.

PACKAGING
Build from a clean venv so the exe only bundles what it needs:

   python -m venv venv
   venv\Scripts\pip install pyinstaller openpyxl xlrd
   venv\Scripts\python -m PyInstaller --onefile --console ^
     --version-file=version_info.txt excel_criteria_data_match.py

version_info.txt embeds author/version into the exe's Properties >
Details tab, so it travels with the exe when forwarded on its own.

KNOWN LIMITATIONS
  - Column letters in the selection codes (e.g. "4_F", "1_D_I",
    "1_D_F:H") are assumed to each be their own token, separated
    by underscores — this was changed deliberately from an
    earlier concatenated format ("4f", "1di") specifically to
    remove any ambiguity for columns beyond Z (e.g. "AA"), at the
    cost of a few extra keystrokes.
  - No fuzzy/partial text matching — a label that's reworded
    between the two sheets will show up as unmatched/overflow
    rather than being matched anyway. This is intentional: silent
    fuzzy-matching on financial figures is a worse failure mode
    than an explicit warning.
  - Only one REFERENCE column and one DATA criteria column per
    run (the DATA side's criteria column is always singular, even
    though it can carry multiple data columns); no batch mode
    across multiple sheet pairs.
  - Screen clearing uses the Windows "cls" command: it works in
    cmd / PowerShell or when double-clicked, not in an IDE output
    panel.
